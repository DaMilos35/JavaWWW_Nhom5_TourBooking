1. BỐI CẢNH & ĐẶT VẤN ĐỀ

Hạn Chế Của Tìm Kiếm Truyền Thống

Tại sao câu lệnh SQL LIKE '%keyword%' không còn đáp ứng được nhu cầu của các sàn OTA hiện đại?

❌ SQL Truyền Thống (Lexical Search)

  • Chỉ so khớp chính xác từng ký tự (Exact Keyword Match).
  • Người dùng gõ: "Chỗ nghỉ dưỡng mát mẻ cho gia đình có em bé" $\rightarrow$ SQL trả về 0 kết quả vì tên tour trong DB là: "Đà Lạt 3N2Đ săn mây thung lũng".
  • Bỏ sót hoàn toàn từ đồng nghĩa: "biển đảo" $\leftrightarrow$ "lặn san hô" $\leftrightarrow$ "cano 4 đảo" $\leftrightarrow$ "resort".

✅ Tìm Kiếm Ngữ Nghĩa (Semantic Search)

  • Hiểu được Ý định & Ngữ cảnh (Intent & Context) của người đi du lịch.
  • Không cần trùng từ khóa: Hiểu rằng "nghỉ dưỡng biển" rất gần gũi với "Phú Quốc resort 5 sao" hay "Nha Trang tắm bùn khoáng".
  • Cho phép tìm kiếm tự nhiên bằng ngôn ngữ đời thường như đang trò chuyện với chuyên viên lữ hành.
Trong thương mại điện tử du lịch, khách hàng tìm kiếm bằng cảm xúc và nhu cầu: "muốn đi trốn nóng", "ngắm tuyết rơi", "ăn hải sản tươi sống". SQL truyền thống hoàn toàn bất lực vì cơ sở dữ liệu lưu tên tour hành chính. Vector Database sinh ra để giải quyết khoảng cách ngữ nghĩa này.
2. ĐỊNH NGHĨA KHOA HỌC

Vector Database Là Gì?

Một hệ thống quản trị cơ sở dữ liệu chuyên biệt được tối ưu hóa để lưu trữ, quản lý và truy vấn các vector số thực nhiều chiều (High-Dimensional Vectors / Embeddings).

Tiêu chí so sánh Relational Database (MariaDB/MySQL) Vector Database (Milvus, Pinecone, Local Vector Store)
Dạng dữ liệu lưu trữ Dữ liệu có cấu trúc (Bảng, Cột, Chuỗi, Số, Ngày tháng) Vector nhúng đa chiều ($[0.125, -0.432, 0.891, ...]$) biểu diễn ngữ nghĩa
Cơ chế đánh chỉ mục B-Tree, B+Tree, Hash Index HNSW (Navigable Small World), IVF-PQ, Cosine Space Index
Phương thức truy vấn So khớp chính xác ($=$, $>$, $<$, $LIKE$, $JOIN$) Tìm kiếm lân cận gần nhất (Nearest Neighbor / Cosine Similarity)
Mục tiêu cốt lõi Toàn vẹn giao dịch ACID, số dư, đơn hàng, bảo mật Tìm kiếm ngữ nghĩa, Đề xuất thông minh, RAG AI Memory
Hãy nhấn mạnh: Vector DB không thay thế RDBMS mà song hành cùng RDBMS. MariaDB quản lý tiền bạc, số chỗ, đơn hàng; còn Vector DB quản lý não bộ tìm kiếm và AI tư vấn.
3. LÝ THUYẾT CỐT LÕI

Vector Embeddings Là Gì?

Cầu nối biến ngôn ngữ phi cấu trúc của con người thành toán học không gian đa chiều.

Văn bản Tour: "Phú Quốc cano 4 đảo lặn san hô"
➔ Mô hình Embedding (Gemini / BERT) ➔
Vector $\vec{v} = [0.241, -0.089, 0.512, ..., 0.177] \in \mathbb{R}^{768}$

🌌 Không Gian Ngữ Nghĩa (Semantic Space)

Các khái niệm có ý nghĩa tương đồng sẽ có vector hội tụ gần nhau. Khoảng cách hình học giữa 2 điểm phản ánh độ tương quan ngữ nghĩa thực tế.

📐 Đại Số Tuyến Tính Trong Ngữ Nghĩa

Công thức kinh điển trong xử lý ngôn ngữ tự nhiên (NLP):
vec("Vua") - vec("Đàn ông") + vec("Phụ nữ") ≈ vec("Nữ hoàng")
Tương tự: vec("Đà Lạt") - vec("Lạnh") + vec("Nắng biển") ≈ vec("Nha Trang")

Vector Embeddings biến chữ viết thành các tọa độ trong không gian 128 chiều hoặc 768 chiều. Nhờ đó, máy tính có thể dùng công thức toán học để so sánh xem hai tour du lịch giống nhau đến mức nào.
4. TOÁN HỌC & ĐỘ TƯƠNG ĐỒNG

Giải Thuật Cosine Similarity

Thước đo góc giữa hai vector trong không gian đa chiều — Giải pháp tối ưu nhất cho văn bản.

$$\text{Cosine}(A, B) = \cos(\theta) = \frac{A \cdot B}{\|A\| \|B\|} = \frac{\sum_{i=1}^{n} A_i B_i}{\sqrt{\sum_{i=1}^{n} A_i^2} \cdot \sqrt{\sum_{i=1}^{n} B_i^2}}$$

🎯 Phổ Điểm Đánh Giá

  • +1.0 ($\theta = 0^\circ$): Hai vector trùng hướng $\rightarrow$ Hoàn toàn đồng nghĩa.
  • 0.0 ($\theta = 90^\circ$): Hai vector trực giao $\rightarrow$ Không liên quan gì đến nhau.
  • -1.0 ($\theta = 180^\circ$): Hai vector đối nghịch hoàn toàn về mặt ngữ nghĩa.

💡 Tại Sao Nhóm 5 Chọn Cosine?

  • Bất biến với độ dài (Scale-invariant): Tour mô tả 500 từ và Tour mô tả 50 từ có chung chủ đề vẫn cho điểm tương đồng cao (khác với Euclidean Distance bị ảnh hưởng bởi độ dài văn bản).
  • Khi vector được chuẩn hóa $L_2$ ($\|A\| = 1$), Cosine Similarity trở thành phép nhân ma trận Dot Product cực nhanh.
Nhóm 5 đã lựa chọn Cosine Similarity vì độ dài mô tả của các tour du lịch thường khác nhau rất nhiều (tour 5 sao viết dài, tour ngắn ngày viết ngắn). Cosine Similarity chỉ quan tâm đến góc lệch ngữ nghĩa, không bị đánh lừa bởi số lượng từ.

8. MÃ NGUỒN CỐT LÕI

EmbeddingService: Cơ Chế Dual-Engine

Thiết kế kỹ thuật xuất sắc giúp hệ thống hoạt động bền bỉ, chạy offline hoặc kiểm thử 100% không phụ thuộc Internet. 

// backend/.../service/EmbeddingService.java
@Service
public class EmbeddingService {
    public static final int LOCAL_VECTOR_DIM = 128;

    public float[] embed(String text) {
        // 1. CHẾ ĐỘ ONLINE: Tích hợp Google Gemini text-embedding-004 (768 chiều)
        if (!geminiApiKey.isBlank()) {
            try {
                float[] onlineVector = callGeminiEmbeddingApi(text);
                if (onlineVector != null && onlineVector.length > 0) return onlineVector;
            } catch (Exception e) {
                log.warn("Gemini API lỗi/mất mạng, tự động chuyển Local Vectorizer");
            }
        }
        // 2. CHẾ ĐỘ OFFLINE FALLBACK: Semantic Projection + L2-Normalized (128 chiều)
        return localSemanticProjection(text);
    }
}
🌐 Chế độ Online: Độ chính xác ngữ nghĩa sâu rộng của mô hình nền tảng Google 768 chiều.
⚡ Chế độ Local Fallback: Không bao giờ gián đoạn dịch vụ, vượt qua 100% các bài test tự động JUnit.
Thầy và hội đồng hãy chú ý giải pháp Dual-Engine này: Đây là điểm chứng minh tư duy kỹ thuật thực tế của sinh viên CNTT. Một hệ thống sản xuất không bao giờ được phép dừng hoạt động chỉ vì nhà cung cấp API bên thứ ba gặp sự cố.

VectorStoreService & Lập Chỉ Mục Metadata

Thuật toán Cosine Similarity trực tiếp trên bộ nhớ kết hợp trích xuất đặc trưng Tour phong phú. 

// Trích xuất đặc trưng đa chiều từ Tour Traveloka (TourVectorIndexer.java)
public static String buildTourDocument(Tour tour) {
    return String.format("Tour: %s. Danh mục: %s. Khởi hành: %s. Giá: %s. Phương tiện: %s. "
        + "Khách sạn: %d sao. Đặc điểm: %s. Điểm nhấn: %s. Mô tả: %s",
        tour.getName(), tour.getCategory().getName(), tour.getDepartureLocation(),
        tour.getPrice(), tour.getVehicle(), tour.getHotelStar(),
        tour.getBadge(), tour.getHighlights(), tour.getDescription());
}

// Tính Cosine Similarity chuẩn xác (VectorStoreService.java)
public double cosineSimilarity(float[] vecA, float[] vecB) {
    double dotProduct = 0.0, normA = 0.0, normB = 0.0;
    for (int i = 0; i < vecA.length; i++) {
        dotProduct += vecA[i] * vecB[i];
        normA += vecA[i] * vecA[i];
        normB += vecB[i] * vecB[i];
    }
    return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB));
}
Trong TourVectorIndexer, nhóm đã nạp toàn bộ các thuộc tính như phương tiện máy bay/du thuyền, số sao khách sạn, điểm nhấn lịch trình vào văn bản vector hóa. Nhờ đó, khách tìm "du thuyền 5 sao" hay "khách sạn 4 sao" đều được Vector DB tìm ra ngay lập tức.

11. TỔNG KẾT & HƯỚNG MỞ RỘNG

Đánh Giá Hiệu Năng & Phát Triển

🏆 Ưu Điểm Đạt Được Trong Đề Tài

  • Tốc độ siêu việt: Truy vấn trên RAM với ma trận ConcurrentHashMap cho độ trễ $\le 5\text{ms}$.
  • Trải nghiệm cá nhân hóa: Tăng tỷ lệ giữ chân người dùng và tỷ lệ chuyển đổi đơn hàng (Conversion Rate).
  • Độ bền vững cao: Cơ chế Dual-Engine giúp vượt qua 100% các bài test tự động JUnit và build Vite sạch 0 lỗi.

🔮 Hướng Phát Triển Tương Lai (Production Scale)

  • Phân tán quy mô lớn: Nâng cấp lên Milvus Distributed Cluster hoặc PostgreSQL với extension pgvector khi quy mô đạt hàng triệu tour.
  • Multimodal Embeddings: Sử dụng mô hình OpenAI CLIP để tìm kiếm tour du lịch bằng hình ảnh phong cảnh do khách tải lên.
  • Lập chỉ mục HNSW: Áp dụng đồ thị thế giới nhỏ phân tầng để tìm kiếm lân cận xấp xỉ trong $O(\log N)$.
Trong tương lai khi dự án thương mại hóa với quy mô hàng triệu tour, nhóm hoàn toàn có thể chuyển dịch kiến trúc In-Memory hiện tại sang cụm phân tán Milvus hoặc pgvector mà không cần thay đổi tầng giao diện người dùng.
